# Finney companion experience

This direction supersedes the earlier dashboard-first walkthrough. The owner
explicitly chose the existing macOS companion as the web reference.

Intent: a busy hackathon director sees what needs them and talks to a personal
agent. The opening is one short situation followed by one actual Finney alert.
Hierarchy: the receipt mascot, one sentence and one useful action; no metric
banner, case revisions, technical attribution, source-ID tabs or provenance menus.
Palette: existing mint, ink and pale neutral surfaces from the approved companion.
Depth: a quiet floating companion surface; ordinary controls use existing tokens.
Surfaces: the existing light canvas and white working surface, with no new theme.
Typography: existing Albert Sans, ordinary body text and one status heading.
Spacing: 8px rhythm, compact controls and generous separation around the one task.

The locked tutorial teaches by interacting with the actual interface: short intro,
open Finney's alert, request the review, see real queued/running state, read the
stored result, open the budget. Other controls are unavailable during each step;
Skip demo remains reachable by pointer and keyboard. Completion depends on the
actual job and persisted output, not a timer, prior result or arbitrary Next button.

Versions, identities and detailed execution records remain in backend/audit
history. Financial approvals still show the amount, destination and meaningful
consequences. Request messages belong in conversation, never among invoice tabs.
Finney's model output should be concise at generation, not silently truncated.

Reference skill: https://github.com/Dammyjay93/interface-design. Its focused-view,
interaction-state and existing-design-system principles supplement the local
Impeccable workflow; the owner's explicit companion reference governs the result.
