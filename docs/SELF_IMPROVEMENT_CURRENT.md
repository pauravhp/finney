# Finney's current self-improvement loop

The latest companion UI release changes the protected user-facing response style
to concise personal-agent prose. It does not change financial authority, output
validation or promotion gates. Those runtime/context changes invalidate the prior
preflight receipt: a newly matched preflight is required before another learning
study. Historical results below remain historical; no study was resumed for the
UI release. The subsequent [primary-response refinement](build/PRIMARY_RESPONSE.md)
uses concise generation with explicit expandable explanation in the same stored
string, without changing the decision schema or financial authority.

Current deployed runtime: OpenCode + Harness2, with **Claude Sonnet 5.5** for the
finance actor, reasoning reviewer, editor and OCR. Jev remains a separate judge.
The active skill remains `baseline-v1`; **no learned promotion has occurred**.
Captured decision-time policy, shared stage vocabulary and safe domain-error
feedback are deployed. The complete history is
[documented separately](SELF_IMPROVEMENT_JOURNEY.md).

## Operating work

While running, Finney autonomously checks the connected finance Gmail label and
queues review of new evidence. Uploads and director prompts also enter durable
jobs. The scoped actor reads case documents, obligations, budgets and cash records,
then records supported findings or proposals. Human decisions and payment execution
remain controlled by the application. An agent may act autonomously without having
unrestricted authority.

## Trace to diagnosis

Each review captures runtime/skill identity, tool arguments and results, source
versions, output, usage, timing and private diagnostics. Jev supplies a triage
signal; it is not the financial authority or the sole promotion judge. Eligible
failed outputs can enter diagnosis while remaining rejected operating results.

A reasoning reviewer must identify a source-supported defect in the mutable
investigation procedure. A policy question, missing evidence, unsupported diagnosis
or protected-authority issue does not become a patch. The recorded example ending
in `policy_question` demonstrates this refusal, not successful self-improvement.

Known source-reference rejections now carry fixed machine-readable reasons and
recovery guidance. Raw provider messages remain private. Diagnosis also receives
deterministic observations when a captured mutation uses a source already known
to be replaced. These observations cite actual earlier reads and arguments; they
do not infer a generic error's cause or force the reviewer to propose a patch.
Operating policy comes from the captured context; evaluation policy belongs to
the frozen synthetic suite and is never substituted into the historical trace.

## Candidate generation

Actual pinned upstream Harness2 executes Propose–Probe–Compose–Reflect through
native OpenCode editor/probe invocations. The editor sees the captured training
evidence and probe observations, not protected answer keys or final cases. Search
uses decision-time snapshots; later sources do not silently repair old evidence.

Only the investigation-procedure body can change. Policy, approval authority,
payment execution, ledger invariants, evaluation answers and gates stay protected.
Search selection is a candidate, not permission to activate it.

## Independent evaluation and activation

The trusted engine freezes baseline/candidate identity and compares both on the
same snapshots. Validation must show correctness gain or fewer tool calls at equal
correctness, with no regression on previously correct cases and no hard-invariant
failure. Protected regression cases must pass. Final transfer cases are consumed
atomically and every candidate transfer result must pass. Failures remain failures;
there is no hidden retry or answer adjustment.

Only the normal protected promotion path can activate a passing candidate. Database
checks independently validate the evidence and compare-and-swap the expected active
version, preventing stale promotion. The standalone benchmark cannot activate a
skill. A demo promotion requires a persisted promotion plus active-version readback.

Online Harness2 attempts reserve at most 96 model calls; ordinary/single-patch
limits and shared run/owner/day caps remain in force. The first larger standalone
benchmark had a separate 480-call ceiling. Call reservations are upper bounds, not
invented dollar costs.

## What the demo can honestly show now

- Actual operating intake, financial records and director replies in the hosted app.
- A real learned candidate and verified diff, validation gain, heldout failures and
  rejection. This is a recorded execution, not freshly running inference.
- Fixed approval boundaries that learning cannot relax.

It cannot yet claim a deployed learned improvement, customer-level accuracy,
measured time savings or verified settlement from the learning experiment. The
current corpus is synthetic with independent AI review. New unseen transfer evidence
must use genuinely fresh cases after policy/evaluator semantics are frozen.
